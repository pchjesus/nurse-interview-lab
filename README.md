# Nurse Interview Lab

간호사 모의면접의 전사본과 평가를 개인별·면접별로 관리하는 정적 웹앱입니다. AI 분석과 음성 전사는 제공하지 않습니다. 전사와 외부 평가 표시, 브라우저 내 PDF 다운로드를 지원합니다. 실제 개인정보를 저장소에 올리지 마세요.

## 사용 순서

별도로 ChatGPT에서 분석 → 권장 1.1 JSON 다운로드 → 면접 기록에서 가져오기와 미리보기 → 참여자를 기존 또는 새 사람에 연결 → 평가 확인 → 개인별 또는 전체 PDF 다운로드 → 설정에서 전체 백업 순으로 사용합니다. 앱의 가상 예시는 직접 선택하기 전에는 저장되지 않으며 실제 임상 근거가 아닙니다. 링크만으로 기록이 공유되거나 동기화되지 않습니다.

## 개발

Node.js 22 이상에서 `npm ci`, `npm test`, `npm run build`, `npm run dev`를 실행합니다. Vite의 GitHub Pages 경로는 `/nurse-interview-lab/`입니다. main 브랜치의 GitHub Actions가 Pages에 배포합니다. 배포 전에 저장소의 Pages 소스를 GitHub Actions로 설정해야 합니다.

[JSON 규격 및 가상 예제](docs/JSON_SCHEMA.md)를 참고하세요. 보고서는 가져오기 전에 검증되며, 사람과 참가자 ID는 별개입니다. 기본 저장은 메모리이며 설정에서 명시적으로 기기 저장을 선택할 수 있습니다. 브라우저 저장소는 같은 출처의 다른 경로와 보안상 격리되지 않습니다. 중요한 데이터는 전체 백업을 별도로 보관하세요.

PDF 및 글꼴 정보는 [PDF 안내](docs/PDF_EXPORT.md), 분석 JSON 작성은 [가져오기 안내](docs/CHATGPT_IMPORT_GUIDE.md)를 참고하세요. 브라우저 통합 검증은 `npx playwright install chromium` 후 `npm run test:e2e`로 실행하며 PDF 검증에 Poppler의 `pdfinfo`와 `pdftotext`가 필요합니다.

## 기능과 개인정보

질문별 또는 전체 발언 순서로 전사본을 확인하고, 원문을 보존한 채 수정할 수 있습니다. 질문별 평가와 출처는 분석자가 제공한 내용이며 앱은 임상적 사실을 검증하거나 공식 병원 평가를 생성하지 않습니다. 개인별·전체 PDF와 전체 JSON 백업을 내려받을 수 있습니다.

데이터는 서버에 자동 저장되거나 친구와 동기화되지 않습니다. 기본 메모리 데이터는 창을 닫으면 사라집니다. 기기 저장을 켠 경우에도 브라우저 데이터를 지우면 기록이 사라질 수 있으므로 정기적으로 백업하세요. 같은 GitHub Pages 출처의 다른 프로젝트와 브라우저 저장소가 완전히 격리되지 않으며, JSON과 PDF에는 개인정보가 포함될 수 있습니다.

릴리스 전 확인 및 복구 절차는 [배포 점검표](docs/RELEASE_CHECKLIST.md)를 참고하세요.

## 처음 사용하는 경우

대시보드의 **단계별 사용법** 또는 헤더의 **사용법**을 선택하면 화면의 실제 위치를 강조하는 안내가 시작됩니다. **가상 데이터로 연습**은 별도 메모리에서 실행되며 연습 종료 시 폐기됩니다. CLOVA Note에서 참여자 동의를 확인해 전사하고, 별도의 ChatGPT 대화에서 근거를 검토한 JSON 1.1을 만든 뒤 가져오세요. 앱은 CLOVA Note나 AI 서비스에 연결하지 않습니다.

기기 저장은 명시적으로 동의할 때 켜지며 이후 변경을 저장합니다. 자동 저장을 일시 중지하면 마지막 기기 저장본은 남고 이후 변경은 메모리에만 있습니다. 영구 삭제는 별도 동작입니다. 다른 최신 버전의 탭에서 먼저 저장하면 덮어쓰기를 중지하므로 현재 화면을 전체 백업한 뒤 새로고침하세요. 이전 버전의 열린 탭은 충돌을 감지하지 못할 수 있으므로 새 버전 사용 전에 닫아 주세요. 브라우저의 지속 저장 요청을 허용해도 영구 보존은 보장되지 않습니다.

서버 저장은 아직 연결되지 않은 기반 단계입니다. 독립 프로젝트, 인증, RLS, 동시 수정 및 데이터 이전의 선행 조건은 [서버 저장 설계](docs/SERVER_STORAGE_DESIGN.md)를 참고하세요. 면접 데이터는 기기에만 저장됩니다. 이메일 OTP 로그인 시에만 전용 인증 서버로 이메일·코드가 전송되며 면접 기록은 전송하지 않습니다.

Supabase SDK 설정은 [서버 저장 설계](docs/SERVER_STORAGE_DESIGN.md)의 비활성 설정 절차를 참고하세요. SDK는 로그인 코드 요청 전 초기화되지 않습니다. 이메일 OTP 로그인은 공개 설정과 전용 프로젝트의 인증 설정이 필요하며, 서버 저장은 아직 사용할 수 없습니다. [인증 설정 안내](docs/EMAIL_OTP_AUTH.md)를 참고하세요.
