# 배포 전 점검표

이 문서는 배포를 승인하거나 실행하지 않습니다. 실제 면접 데이터나 교재는 테스트·저장소·Actions 산출물에 넣지 않습니다.

## 배포 전

- `npm ci`, `npm test`, `npm run build`, `npx playwright install --with-deps chromium`, `npm run test:e2e`를 실행하고 실패를 해결한다. PDF 텍스트 검증에는 Poppler가 필요하다.
- GitHub Actions의 해당 커밋 검증 결과를 확인한다. `main` 변경 시 Pages 배포 작업이 실행되므로 병합은 별도 승인 후 진행한다.
- 저장소 Settings → Pages에서 소스를 GitHub Actions로 설정한다. Vite base는 `/nurse-interview-lab/`이며 환경변수와 API 키는 필요하지 않다.
- 가상 1.1 보고서와 기존 1.0 보고서를 가져와 미리보기, 사람 연결, 전사 보기, 평가와 출처를 확인한다. 잘못된 파일이 기존 데이터를 바꾸지 않는지 확인한다.
- 가상 데이터로 개인·전체 PDF의 한글, 페이지 번호, 내용과 사람별 분리를 확인한다. 모바일의 스크롤·입력·다운로드도 확인한다.
- 기기 저장 선택, 재시작, 삭제, 전체 백업과 복원을 확인한다. 브라우저 저장소 삭제·동일 출처 공유·다운로드 개인정보 위험을 안내한다.
- 추적 파일과 배포 산출물에 실제 녹음, 교재, 전사, 개인정보나 비밀 값이 없는지 확인한다. 임상 근거는 앱에서 검증하지 않는다.

## 승인된 배포와 복구

- 승인된 main 커밋의 Actions 배포 성공과 Pages 프로젝트 경로의 실제 자산·PDF 글꼴 로딩을 확인한다. 실제 사용자 데이터는 올리지 않는다.
- 문제가 발생하면 별도 승인 후 이전에 검증한 main 커밋으로 되돌리는 revert를 준비하고 빌드·배포를 다시 검증한다. 단순 코드 롤백은 브라우저 저장 데이터를 복구하지 않는다.
- 사용자의 기존 JSON 전체 백업을 보존한다. 데이터 복원이 필요하면 새 백업을 먼저 만들고, 호환성을 확인한 뒤 사용자가 복원을 실행한다.
