# 이메일 OTP 인증 설정

이 앱은 사용자가 로그인 버튼을 열고 이메일 코드 요청을 선택할 때에만 전용 Supabase Auth로 요청합니다. 기존 계정만 로그인할 수 있도록 `shouldCreateUser: false`를 사용합니다. 자동 테스트는 가상 응답을 사용하며 실제 메일을 보내거나 계정을 생성하지 않습니다.

## 프로젝트 설정 확인

1. 전용 프로젝트 `aevhsdqrirgslfetknip`의 Auth에서 이메일 제공자가 활성화되어 있는지 확인합니다. 실제 프로젝트 설정은 이 코드가 변경하지 않습니다.
2. 이메일 OTP 템플릿에서 매직링크 대신 `{{ .Token }}`을 표시하고, 발급되는 코드 길이가 이 앱의 6자리 입력과 일치하는지 확인합니다. 코드 만료 시간, 재요청 제한 및 메일 발송 설정은 프로젝트에서 관리합니다.
3. 사용자 사전 등록·초대 정책을 별도로 결정합니다. 이 앱은 OTP 요청에서 신규 계정을 자동 생성하지 않습니다. 계정 등록이나 초대 메일 발송은 이번 작업에서 수행하지 않습니다.
4. `.env.example`을 `.env.local`로 복사하고 해당 프로젝트의 publishable 공개 키를 입력한 뒤 앱을 빌드합니다. `VITE_` 값은 브라우저에 공개되므로 secret·service_role 키를 넣지 마세요.

OTP 코드 입력 방식은 이메일 리다이렉트를 사용하지 않습니다. 향후 다른 인증 방식이 추가된다면 정확한 앱 URL만 리다이렉트 허용 목록에 등록하고 별도 검증해야 합니다.

## 세션과 데이터 경계

세션은 앱 메모리에만 보관하고 자동 로그인·영구 토큰 저장·토큰 자동 갱신을 사용하지 않습니다. 새로고침 또는 세션 만료 후 다시 로그인해야 합니다. 로그아웃 시 기기 기록은 유지되며 서버 로그아웃을 확인하지 못한 경우 그 상태를 알립니다. 동일 GitHub Pages 출처의 다른 스크립트가 페이지에 접근할 수 있으므로 메모리 세션도 XSS나 악성 스크립트에 대한 보안 경계가 아닙니다.

인증 표시 상태는 접근 제어가 아닙니다. 서버 저장은 미연결이며 면접 데이터는 업로드하지 않습니다. 향후 RLS와 서버 측 토큰 검증을 별도로 구현·검증해야 합니다. 이 단계에서는 실제 이메일 전달, OTP 만료 정책과 Supabase 세션을 검증하지 않았습니다.
